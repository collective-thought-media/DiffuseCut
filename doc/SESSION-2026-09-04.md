## 1. Delete project (two modes)

Users can remove a project from DiffuseCut without always deleting files on disk.

| Mode | Behavior |
|------|----------|
| **Remove from app, keep media** | Deletes DB records; project folder stays on disk. API returns `keptMediaPath`. |
| **Delete project and media** | Deletes DB records and removes the project root via `fs.rmSync`. |

## 5. Cursor jump bug fix (critical)

**Problem:** While typing in text fields, the caret jumped to the end of the input. Autosave returned server state that overwrote in-progress edits.

**Root cause:** Patterns like `useEffect(() => { setLocal(prop) }, [state])` in state panels, and storyboard `saveShot` replacing the full shot object from stale API responses.

### Solution

1. **`src/lib/hooks/useSyncedEditableFields.ts`** — Local form state syncs from props only when `entityKey` changes; skips prop→local sync for **focused** fields.
2. **`src/lib/hooks/useDebouncedSave.ts`** — Epoch counter per `schedule()`; save callbacks receive `ctx.isLatest()` and skip parent state updates when superseded.
3. Migrated autosave forms to the hook + stale-save guards.

### Pages and panels updated

- `src/app/projects/[projectId]/page.tsx` (logline, plot)

## 6. Seamless backdrop generation (BTS studio problem)

**Problem:** Location reference prompts for gray seamless / cyclorama setups produced wide behind-the-scenes studio shots (paper rolls, C-stands, floor lines) instead of in-camera backdrop plates.

**Why:** Default location suffix asked for “wide framing with full environment visible.” Describing studio gear in user text makes SDXL render the setup, not what a portrait camera sees.

### Prompt pipeline changes

- **`src/lib/location-backdrop.ts`** — Client-safe `detectVirtualBackdropLocation()` (no server/db imports).
- **`src/lib/services/prompt-preprocess.ts`** — Backdrop-specific prefix/suffix/negatives; in-camera language; anchor variants for tight reframes; `buildBackdropCameraDirective()`.
- **`src/lib/services/llm-prompt-expand.ts`** — Backdrop-aware LLM system prompt; location preview uses draft prompt in user message.
- **`src/lib/anchor-reframe.ts`** — Extracted reframe intensity helpers (shared by server + client).
- **`src/lib/ip-adapter-profiles.ts`** — Extracted IP-Adapter weight profiles.

### UI hints

- `LocationReferenceGenerator.tsx` — Amber banner when backdrop detected.
- `LocationStatesPanel.tsx` — View description placeholder mentions seamless in-camera framing.

### Build fix

Importing `detectVirtualBackdropLocation` from `prompt-preprocess.ts` in a client component pulled in `better-sqlite3` → **Module not found: Can't resolve 'fs'**. Detection lives in `location-backdrop.ts`; server code re-exports from there.

### Recommended field pattern (virtual backdrop)

| Field | Guidance |
|-------|------------|
| Location description | Surface color/tone only. No softboxes, stands, or “photo studio.” |
| View description | In-camera: “gray seamless fills frame edge to edge, no floor, no equipment.” |
| Angle name | Short label only (e.g. `Gray backdrop medium`, `Head and shoulders zone`). |

## 7. Per-angle IP-Adapter controls

**Problem:** Global auto IP-Adapter tuning was insufficient. A good medium anchor still produced tight angles with visible studio gear or wider framing than requested.

### Feature

Each **anchored** location angle generator now exposes an **Anchor reference** panel:

| Mode | Behavior |
|------|----------|
| **Auto** | App picks weight/end_at from angle description (via `resolveLocationAnchorReframeIntensity`). |
| **Custom IP-Adapter influence** | Sliders: anchor influence (weight 0.10–0.65), apply through (end_at 20–75% of steps). |
| **Prompt only** | Forces txt2img; ignores saved anchor image for this batch. |

Seamless backdrop angles default to **Custom** at weight **0.28**, end_at **0.38** (`BACKDROP_TIGHT_IP_ADAPTER_DEFAULTS`).

### Persistence

- `asset_generation_batches.generation_options_json` — stores `{ useIpAdapter?, ipAdapterWeight?, ipAdapterEndAt? }` per batch.
- Worker reads options and applies `ipAdapterOverrides` in `buildPortraitPayload`, or skips IP-Adapter template when `useIpAdapter: false`.
